# Deployment

The distributed APK is R8-optimized and signed with one persistent debug key. Google authentication uses OIDC, not a JSON service-account key.

## Access boundaries

- Pull-request checks get no deployment secrets or cloud credentials.
- Delivery runs only on main, through environment `firebase-distribution`.
- OIDC checks numerical owner/repository IDs, main ref, exact workflow path, and push/manual event.
- The service account gets project-level App Distribution access, not general project administration.
- The workflow never runs untrusted fork code in a privileged context.
- Automatic delivery runs for Android source/build/branding changes. Documentation and deployment-configuration-only changes do not resend an APK; use manual dispatch with a new version when testing a delivery change.

## Google setup

Review and run `scripts/setup-oidc.sh PROJECT_ID` with authenticated Google Cloud CLI and GitHub CLI. This creates a dedicated service account, workload identity pool/provider and narrow trust bindings, then writes non-secret GitHub environment variables.

Register a **new** Android app, not the existing home-screen widget:

```sh
firebase apps:create ANDROID "Charging Optimization Tile" \
  --package-name com.kissedcode.chargingtile --project PROJECT_ID
gh variable set FIREBASE_APP_ID --repo kissedcode/charging-optimization-tile \
  --env firebase-distribution --body '1:PROJECT_NUMBER:android:APP_IDENTIFIER'
```

No Google private key is generated by the setup script. Review existing resources before rerunning the script: it owns the dedicated `charging-tile-gh` pool and `github-main` provider.

In Google Cloud Shell, use `SKIP_GITHUB_CONFIG=1 bash scripts/setup-oidc.sh PROJECT_ID` to avoid requiring GitHub authentication there. It prints only non-secret variable values; set those in GitHub separately. Confirm `gcloud auth list` uses the intended personal Google account before running any setup.

## Secrets

In environment `firebase-distribution`, set `ANDROID_DEBUG_KEYSTORE_BASE64` and `FIREBASE_TESTERS` (comma-separated approved tester addresses).

Create a signing key only once, outside the source tree, and keep a private backup:

```sh
keytool -genkeypair -keystore /private/path/charging-debug.keystore \
  -storetype JKS -alias androiddebugkey -storepass android -keypass android \
  -keyalg RSA -keysize 2048 -validity 10000 \
  -dname 'CN=Android Debug,O=Android,C=US'
base64 < /private/path/charging-debug.keystore | tr -d '\n' | \
  gh secret set ANDROID_DEBUG_KEYSTORE_BASE64 \
    --repo kissedcode/charging-optimization-tile --env firebase-distribution
```

Debug passwords are not production-strength key protection. Keep the keystore private: possession can authorize updates of this privileged app. Use GitHub's secret form for tester addresses; never put them in public files.

## Release checks

Increase both `versionCode` and `versionName` for each new delivery. Keep applicationId unchanged. APK filename example: `charging-optimization-tile-0.1.0-debug.apk`.

The workflow checks R8 mapping, APK signature, requires `testOnly=true` (hidden Settings.Secure keys are only readable by test-only apps) and forbids `debuggable`, and rejects duplicate/older Firebase versionCodes. Rerunning an already distributed version fails the duplicate check rather than sending another notification.

Before the first upload, Firebase may return 404 for the release collection. Only versionCode 1 can bootstrap, and only after the Firebase Management API confirms an active Android registration with the exact App ID, project and APK package name. Other 404/403 errors remain failures.

Artifacts contain the APK, R8 mapping and build metadata, never signing or Google credentials. A successful artifact upload followed by a Firebase error is a failed deployment.

Firebase CLI's temporary binary-download URL is filtered out of public logs. Stable tester and Firebase console links remain visible; the shell retains `pipefail` so output filtering cannot hide a distribution failure.

## GitHub Release

Each delivery also creates a GitHub Release `v<versionName>` with the APK, R8 mapping and build metadata, because test-only APKs cannot be installed through the Firebase tester UI. Install with `adb install -t -r`.

## Device acceptance

After installation:

```sh
adb shell pm grant com.kissedcode.chargingtile android.permission.WRITE_SECURE_SETTINGS
```

Verify 80% ↔ Off, external Adaptive → 80%, long press, locked-phone behavior, error handling and update-over-install on the Pixel. Passing CI does not establish firmware compatibility.

The direct charging-settings intent is resolved at runtime and restricted to an exported system activity. Battery settings are the fallback.

The design follows [Google Cloud WIF](https://docs.cloud.google.com/iam/docs/workload-identity-federation-with-deployment-pipelines), [Google's auth action](https://github.com/google-github-actions/auth), [Firebase CLI distribution](https://firebase.google.com/docs/app-distribution/android/distribute-cli) and [Android update requirements](https://developer.android.com/google/play/app-updates).
