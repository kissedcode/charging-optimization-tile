# Charging Optimization Tile: спецификация

Версия документа: 2026-10-20 (ревизия 2).
Статус: реализована и проверена на Pixel 9 Pro (Android 16, CP1A.260505.005): чтение режима, 80% ↔ Off, системный экран зарядки.
Текущая инсталляция: APK `0.1.1-debug` (2), test-only, `com.kissedcode.chargingtile`, Firebase project `charging-widget-kissed`, minSdk 35, targetSdk/compileSdk 36, целевой телефон Pixel 9 Pro.
Назначение: показывать текущий режим оптимизации зарядки в панели быстрых настроек и переключать ограничение 80% одним нажатием.

## Часть 1: Пользовательская

### Что это за приложение

Небольшая утилита с плиткой в панели быстрых настроек и экраном первоначальной настройки. Существующий отдельный виджет домашнего экрана остаётся без изменений.

- **Обычный тап:** переключает только «Лимит 80%» и «Выкл».
- **Долгое нажатие:** открывает системную настройку оптимизации зарядки.
- **Текущий статус:** берётся из системы, а не из последнего нажатия внутри приложения.
- **Работа без сети:** нет аккаунта, рекламы, аналитики или облачного хранения пользовательских данных.

### На каких устройствах работает

Первое целевое устройство: Google Pixel 9 Pro со штатной прошивкой Google и Android 15 или новее. Установленная версия Android пока не уточнена; реальную совместимость подтвердим на телефоне.

Поддержка других моделей и GrapheneOS не заявляется. Если требуемые настройки недоступны, приложение сообщает об этом и не пытается угадывать состояние.

### Что видит пользователь при первом запуске

Один экран показывает текущий режим, статус разрешения, команду для разовой настройки и кнопки:

```text
Charging Optimization Tile
Текущий режим
Разрешение на переключение
Добавить плитку
Скопировать команду
Проверить разрешение
Открыть настройки зарядки
```

Варианты статуса разрешения:

```text
Разрешение выдано
Нужна разовая настройка через компьютер
```

Информационное пояснение:

```text
Нажатие переключает лимит 80% и выключенную оптимизацию.
Долгое нажатие открывает системные настройки зарядки.
```

### Пользовательские сценарии

#### Добавить плитку

Нажатие «Добавить плитку» вызывает системное предложение добавить её в панель. Порядок и расположение плиток пользователь определяет в редакторе Android; приложение не меняет существующие плитки.

Сообщения результата:

```text
Плитка добавлена
Плитка уже добавлена
Плитка не добавлена. Её можно добавить через редактор быстрых настроек.
Не удалось показать предложение. Добавьте плитку через редактор быстрых настроек.
```

#### Посмотреть режим

Основная подпись плитки:

```text
Зарядка
```

Подпись состояния:

```text
Лимит 80%
Выкл
Адаптивная
Неизвестно
```

Лимит 80% подсвечивается; выключенная оптимизация не подсвечивается. Если Adaptive включили через системные настройки, плитка честно отображает «Адаптивная», но не предлагает этот режим в цикле нажатий.

#### Переключить режим

- **Из «Лимит 80%»:** отключить ограничение и адаптивную зарядку, показать «Выкл».
- **Из «Выкл»:** включить лимит 80%.
- **Из «Адаптивная»:** включить лимит 80%; это правило предлагается для первой версии.
- **Из «Неизвестно»:** ничего не записывать, открыть экран приложения с объяснением.
- **Без разрешения:** ничего не записывать, открыть экран первоначальной настройки.
- **На заблокированном телефоне:** сначала запросить разблокировку; отмена не меняет режим.

«Выкл» означает отключение этих двух вариантов оптимизации. Приложение не отключает защиту от перегрева и другие системные ограничения зарядки.

При ошибке не показывать успешное переключение. Пользовательские сообщения:

```text
Не удалось прочитать режим зарядки на этом устройстве.
Не удалось переключить режим. Проверьте системные настройки.
Нужно разрешение через компьютер. Инструкция показана ниже.
```

#### Открыть системные настройки

Долгое нажатие ведёт на страницу Charging optimization, если она доступна для открытия из приложения на этой прошивке. Если прямой переход недоступен, открыть раздел «Батарея» и сообщить:

```text
Откройте «Оптимизация зарядки» в настройках батареи.
```

Раздел Battery Saver не используется. Если даже раздел батареи недоступен, открыть общие системные настройки; при полном отказе запуска показать сообщение об ошибке.

#### Установить обновление

Тестовая сборка приходит через Firebase App Distribution. Имя файла заканчивается на `-debug.apk`; обновления должны устанавливаться поверх предыдущей версии этого нового приложения.

Это отдельное приложение, не обновление старого домашнего виджета. Старый виджет не удаляется.

### Экраны и виджеты

- **Экран настройки:** текущий статус, разрешение, инструкция и кнопки.
- **Плитка быстрых настроек:** статус, обычное и долгое нажатие.
- **Домашний виджет:** не входит в новое приложение.
- **Постоянное уведомление:** отсутствует; постоянно работающий фоновый процесс не проектируется.

### Требования к настройке

Android не отдаёт скрытые настройки зарядки обычным приложениям, поэтому сборка помечена как test-only: установка и каждое обновление выполняются с компьютера командой `adb install -t -r <apk>`. Кнопка установки в Firebase App Distribution для такой сборки не работает; Firebase остаётся уведомлением о новой версии, а сам APK берётся из GitHub Releases или из письма Firebase.

После первой установки нужно один раз выполнить команду выдачи разрешения, показанную приложением. Разрешение сохраняется при обновлениях с той же подписью.

После настройки отключить USB-отладку, если она больше не нужна. Приложение при каждом запуске проверяет наличие разрешения, а не предполагает, что оно сохранилось.

### Границы функциональности

Нет собственного алгоритма зарядки, произвольного процента ограничения, графиков, статистики, расписаний и переключения Adaptive из плитки. Проверка системного значения не равнозначна измерению реального тока зарядки.

## Техническая спецификация для реализации

### Детали: Цель и границы системы

Новый публичный репозиторий `kissedcode/charging-optimization-tile`. История, личные сведения и конфигурация существующего приватного проекта не переносятся; его видимость не изменяется.

Управление ограничено двумя настройками Pixel. Их использование является зависимостью от реализации прошивки, а не обещанием универсального Android API.

### Детали: Архитектура

- **Фиксированные версии:** Kotlin 2.1.21, AGP 8.11.1, Gradle wrapper 8.14.3, JDK 17; обновления зависимостей рассматриваются отдельно, предупреждения lint только о наличии более новых версий исключены из блокирующих проверок.
- **SDK:** minSdk 35, compileSdk 36, targetSdk 36.
- **UI:** Jetpack Compose Material 3, версии зависимостей фиксируются в version catalog; без динамических версий.
- **Данные:** система является источником истины; постоянного собственного хранилища состояния нет.
- **Асинхронность:** coroutines; чтение и запись через репозиторий, операции переключения сериализованы.
- **Обновления:** чтение при появлении плитки и при возобновлении Activity; ContentObserver только во время отображения.
- **Сетевые зависимости:** Firebase SDK, Google Services plugin, INTERNET permission не нужны для функциональности приложения и не включаются.

### Детали: Package name / applicationId

`com.kissedcode.chargingtile` для всех распространяемых сборок. Суффикс `-debug` используется в имени APK и версии, но не меняет applicationId.

### Детали: AndroidManifest

- **MainActivity:** exported, MAIN/LAUNCHER; экран первоначальной настройки.
- **ChargingSettingsActivity:** exported, обработчик `android.service.quicksettings.action.QS_TILE_PREFERENCES` с категорией DEFAULT; защищён `android.permission.BIND_QUICK_SETTINGS_TILE`; перенаправляет в системные настройки и завершает работу.
- **ChargingTileService:** exported, защищён `android.permission.BIND_QUICK_SETTINGS_TILE`, intent-filter `android.service.quicksettings.action.QS_TILE`; non-active mode, без `ACTIVE_TILE=true`.
- **Разрешение приложения:** `android.permission.WRITE_SECURE_SETTINGS`.
- **Не запрашиваются:** INTERNET, уведомления, foreground service, Accessibility, overlay, root.
- **Backup:** отключён, собственных пользовательских данных нет.
- **Receivers/providers:** не требуются.

Контракт TileService, жизненный цикл и открытие Activity через PendingIntent берутся из [Android Developers](https://developer.android.com/reference/android/service/quicksettings/TileService).

### Детали: Разрешения и как они получаются

Точная команда:

```bash
adb shell pm grant com.kissedcode.chargingtile android.permission.WRITE_SECURE_SETTINGS
```

Команду выполняют после установки и явного разрешения USB-отладки на телефоне. Никакой попытки скрытой выдачи permission или обхода системы.

Для отзыва:

```bash
adb shell pm revoke com.kissedcode.chargingtile android.permission.WRITE_SECURE_SETTINGS
```

`BIND_QUICK_SETTINGS_TILE` является защитой экспортируемых компонентов, а не разрешением, которое нужно выдавать приложению через ADB.

### Детали: Ресурсы и локализация

Все пользовательские строки из части 1 хранятся в ресурсах. Базовый язык `values/`: английский; `values-ru/`: русский. На телефоне с английским языком плитка показывает `Charging`, `80% limit`, `Off`, `Adaptive`, `Unknown`.

Иконки статусов: батарея с отметкой 80, батарея без лимита, часы для Adaptive, знак вопроса для Unknown. Семантика не зависит только от цвета.

Поддерживаются тёмная тема, крупный шрифт и TalkBack. Дополнительные сообщения системных API локализует Android.

### Детали: Брендинг

Минималистичная батарея с отметкой 80; фон тёмно-синий `#102A43`, акцент бирюзовый `#40C9A2`. Это предлагаемый дизайн первой версии.

Обязательны `branding/icon-source.png` 1024×1024, legacy launcher icons всех плотностей, adaptive icon и monochrome icon. Проверка сборки падает при отсутствии исходника, `mipmap-xxxhdpi/ic_launcher.png` или `mipmap-anydpi-v26/ic_launcher.xml`.

### Детали: Взаимодействие с системой

| Настройка Settings.Secure | Интерпретация |
|---|---|
| `charge_optimization_mode` | 1: Limit80; 0: состояние определяется вторым ключом |
| `adaptive_charging_enabled` | При первом ключе 0: 1 означает Adaptive, 0 означает Off |

Чтение через `getString` с явной обработкой отсутствующего/нечислового значения; не использовать default=0. При первом ключе 1 режим Limit80 определяется независимо от второго; при первом ключе 0 необходим валидный второй ключ; остальные значения означают Unknown.

Механизм записи этих Pixel-настроек с ADB-разрешением применён в [ChargeQuickTile](https://github.com/TebbeUbben/ChargeQuickTile); совместимость конкретного телефона всё равно проверяется отдельно.

### Детали: Основные пользовательские потоки

#### Отображение плитки

В `onStartListening` зарегистрировать observer на оба URI, прочитать значения, обновить icon/label/subtitle/state/contentDescription и вызвать updateTile. В `onStopListening` снять observer; не держать постоянный процесс ради плитки.

Такое обновление соответствует non-active жизненному циклу, описанному в [Android Developers](https://developer.android.com/develop/ui/views/quicksettings-tiles).

Limit80 и Adaptive: `STATE_ACTIVE`; Off: `STATE_INACTIVE`. Unknown отображается с `STATE_INACTIVE`, чтобы сохранить доступ к экрану диагностики по нажатию; не маскировать его подписью Off.

#### Переключение

1. При необходимости вызвать unlockAndRun; после разблокировки повторно проверить разрешение и прочитать режим.
2. При отсутствии разрешения или Unknown открыть MainActivity через immutable activity PendingIntent и startActivityAndCollapse.
3. Захватить mutex; повторно прочитать состояние, не принимать решение по устаревшей подписи.
4. Из Limit80 записать `adaptive_charging_enabled=0`, затем `charge_optimization_mode=0`.
5. Из Off/Adaptive записать `adaptive_charging_enabled=0`, затем `charge_optimization_mode=1`.
6. Проверить результат обоих putString/putInt, перечитать ключи, отобразить фактическое состояние.
7. При исключении/частичном отказе ничего не объявлять успешным: перечитать состояние и показать ошибку в Activity. Две записи не считаются атомарной транзакцией; не выполнять слепой rollback, способный перетереть внешнее изменение.
8. Быстрые повторные нажатия во время записи игнорировать, а не накапливать в очередь.

#### Долгое нажатие

Обработать QS_TILE_PREFERENCES в отдельной Activity. Прямой action `com.google.android.settings.intelligence.action.CHARGING_OPTIMIZATION` разрешается во время выполнения только в экспортируемую системную Activity. Его наличие в Pixel-реализациях подтверждается [описанием Amply](https://github.com/d4rken-org/amply/issues/49); работа на конкретном телефоне пока не проверена.

Далее fallback `Intent.ACTION_POWER_USAGE_SUMMARY`, затем `Settings.ACTION_SETTINGS`. Обрабатывать ActivityNotFoundException и SecurityException. До проверки на устройстве прямой переход имеет статус «не подтверждён».

### Детали: Сборка, debug-подпись и R8

Распространяемый build type `internal` наследует release-конфигурацию:

```text
isDebuggable = false
isMinifyEnabled = true
isShrinkResources = true
default ProGuard config = proguard-android-optimize.txt
signing = постоянный debug-keystore
```

Debug относится к подписи и маркировке тестовой сборки, а не к отключению оптимизации. Эти настройки code/resource shrinking соответствуют [документации R8](https://developer.android.com/topic/performance/app-optimization/enable-app-optimization).

Debug-keystore создаётся один раз для нового приложения. Хранить его в repository/environment secret `ANDROID_DEBUG_KEYSTORE_BASE64`; стандартные debug alias/password не требуют отдельной сложной схемы секретов. Сам keystore не коммитить и не публиковать как artifact.

При отсутствии стабильного keystore workflow доставки завершается понятной ошибкой, не генерирует новый ключ молча. Владелец сохраняет локальную резервную копию. Стабильная подпись нужна для обновления поверх установленного приложения по [правилам Android](https://developer.android.com/google/play/app-updates).

APK обязан иметь `android:testOnly="true"`: `SettingsProvider.enforceSettingReadable` на Android 12+ бросает `SecurityException` при чтении скрытых ключей `Settings.Secure` (в том числе `charge_optimization_mode`, `adaptive_charging_enabled`) для обычных приложений и делает исключение только для system/platform-signed и test-only приложений; `WRITE_SECURE_SETTINGS` на чтение не влияет. Это подтверждено на устройстве: версия 0.1.0 без флага показывала Unknown при корректных значениях ключей, версия 0.1.1 с флагом читает и пишет. Следствие: установка только через `adb install -t -r`. Workflow проверяет наличие флага и запрещает `debuggable`. Имя: `charging-optimization-tile-<versionName>-debug.apk`, где versionName в имени приводится к одному суффиксу, без `-debug-debug`.

В репозитории хранятся базовые versionName и versionCode; каждое изменение для распространения увеличивает обе версии. Повторный запуск уже распространённой версии отклоняется проверкой дубликатов. R8 mapping сохраняется отдельно рядом с артефактом соответствующей сборки.

### Детали: GitHub Actions

- **Pull request:** lint, unit tests, сборка оптимизированного проверочного APK с временной debug-подписью, без Firebase и без постоянных секретов. Этот APK не распространяется.
- **Push в main:** те же проверки; при изменениях app/build/branding выполняется доверенная сборка с постоянной debug-подписью и доставка. Правки документации и только конфигурации доставки не вызывают повторную рассылку; для них есть ручной запуск с новой версией.
- **Ручной запуск:** workflow_dispatch только для main; другие refs не допускаются к доставке.
- **Права:** contents:read по умолчанию; id-token:write только в job доставки.
- **Изоляция:** отдельное environment `firebase-distribution`, разрешена только main. Не использовать pull_request_target и не выполнять код из fork с секретами.
- **Зависимости:** actions фиксируются на проверенные commit SHA; Gradle wrapper с проверкой checksum; версии CLI и зависимостей фиксируются.
- **Артефакты:** APK, R8 mapping, результаты тестов; никаких credentials, keystore, файлов auth и полных дампов переменных окружения.
- **Сериализация:** доставки main выполняются последовательно; перед доставкой отсеивать устаревший commit и уже выпущенную версию. Не отменять выполняющуюся загрузку ради новой.
- **Первый релиз:** 404 списка релизов допускается только для versionCode 1 и после проверки ACTIVE Android-регистрации с точным appId/projectId/packageName через Firebase Management API. Остальные 404/403 не игнорируются.
- **Финальный статус:** различать успешную сборку и успешное распространение. Отсутствие OIDC-конфигурации не считается успешным деплоем.

Предостережения об обработке недоверенного кода с секретами изложены в [GitHub Docs](https://docs.github.com/en/actions/reference/security/securely-using-pull_request_target).

### Детали: Внешние интеграции и OIDC

План: новая Android-регистрация в существующем Firebase-проекте `charging-widget-kissed`, без изменения старого Android-приложения. Использование проекта и текущие полномочия необходимо проверить перед облачными изменениями.

Создать отдельный service account для доставки этого приложения. Выдать `roles/firebaseappdistro.admin` в выбранном проекте, без Owner/Editor; эта роль даёт доступ к App Distribution проекта, а не только одной Android-регистрации, согласно [Google Cloud IAM](https://docs.cloud.google.com/iam/docs/roles-permissions/firebaseappdistro).

Создать выделенные Workload Identity Pool/Provider или безопасно использовать существующие после проверки, не расширяя доверие других репозиториев. Условия доверия ограничивают:

- числовой `repository_owner_id` пользователя;
- числовой `repository_id` нового репозитория;
- `ref == refs/heads/main`;
- конкретный workflow доставки;
- события push/workflow_dispatch, без PR.

Числовые идентификаторы и attribute conditions предусмотрены [Google Cloud Workload Identity Federation](https://docs.cloud.google.com/iam/docs/workload-identity-federation-with-deployment-pipelines).

Разрешить выбранному principal impersonation только этого service account через `roles/iam.workloadIdentityUser`. Постоянный JSON-ключ Google и FIREBASE_TOKEN не создавать.

В workflow использовать `google-github-actions/auth` с временными ADC credentials; аутентификация выполняется непосредственно перед Firebase CLI, после сборки. Удаление временных credentials обязательно; схема описана в [google-github-actions/auth](https://github.com/google-github-actions/auth).

Repository/environment variables:

```text
FIREBASE_PROJECT_ID
FIREBASE_APP_ID
GCP_WORKLOAD_IDENTITY_PROVIDER
GCP_SERVICE_ACCOUNT
```

Repository/environment secrets:

```text
ANDROID_DEBUG_KEYSTORE_BASE64
FIREBASE_TESTERS
```

`FIREBASE_TESTERS` содержит согласованных двух стандартных тестеров владельца, передаётся в `--testers` каждой доставки и не публикуется в исходниках, SPEC, README, release notes или логах. Дополнительные тестеры из старого проекта автоматически не переносятся. Адреса хранятся только в непубличной конфигурации.

Доставка через Firebase CLI с `--app`, явными тестерами и короткими release notes; требуется подписанный APK согласно [Firebase CLI distribution](https://firebase.google.com/docs/app-distribution/android/distribute-cli). SDK Firebase в APK для выбранной схемы не добавляется.

### Детали: Нефункциональные требования

- **Безопасность:** отсутствие сетевого доступа приложения; не хранить пользовательские credentials; проверка доступности системных компонентов и разрешений.
- **Надёжность:** неизвестные состояния не считать Off; после записи проверять результат; внешние изменения отражать при открытии панели.
- **Производительность:** нет polling, foreground service, boot receiver или постоянного уведомления.
- **Публичный репозиторий:** никаких личных адресов тестеров, ключей, локальных путей пользователя и приватной истории.
- **Отладка:** minified APK проверяется отдельно; диагностические сообщения не содержат посторонних системных настроек. HTTP-ошибки проверки релиза не сериализуют headers или объекты credentials в CI-лог.
